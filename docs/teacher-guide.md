# 教師維護指南

## 上課前

第一週只用 MakeCode 模擬器，前七關必達，後三關視程度安排。第二週才準備 micro:bit 與資料 USB 線。第三週一塊板子的 A/B 分別代表雙隊；A+B 重置。LED 實體為單色。

## 建立真實繳交入口

1. 使用學校核准帳號建立五份 Google 表單。建議欄位：班級代號、學生代碼、作品名稱、MakeCode 分享連結、網頁網址、心得、截圖／影片連結。
2. 選擇是否要求登入。若使用檔案上傳題，先以學生帳號測試 Workspace 政策；不要宣稱匿名上傳一定可用。無登入需求可採分享連結加心得，檔案依校內方式保存。
3. 表單回應及關聯試算表僅授權教師查看。不要開啟可讓學生瀏覽其他回應的設定。
4. 將學生填答網址寫入 assignments.js，開啟 open。不可把回應試算表或編輯網址放入公開程式碼。
5. build 後部署。實際填一筆不含真實學生個資的測試回應，在表單後台確認收到，再刪除測試資料。
6. 學生端只能說「前往表單填寫」；網站無法推定已送出。學生本機完成勾選不是交件紀錄。

教師從自己的 Google 表單後台開啟回應試算表，按週次／班級代號／學生代碼檢視作品。評量面向為可操作、符合要求、能說明原理、如實測試。回饋請透過學校核准的私人管道交給學生，別將私人回應嵌進此公開靜態網站。

## 新增與修改教材

任務頁現在並列「MakeCode 與動手操作」及「AI 提示詞輔助」。先示範與實作，再請學生把功能、工具、操作及預期結果說清楚。右欄可整理與複製提示詞，貼到教師指定工具；不會在本站直接獲得 AI 回應。兩欄使用同一任務目標與基本驗收。若學生自訂想法更改按鍵或輸出，提示詞會要求 AI 先指出差異、確認後另列修改版測試。

第一週前三關提供老師示範與學生練習範例。第四、五週有些工作屬於網頁與資料操作，左欄會明確說明，不能宣稱全都使用積木。請提醒學生一次只請 AI 教一步，親自測試後回報；AI 說完成不等於實際完成。

在 data/tasks.js 編輯任務。每個任務保留一個新概念，步驟先少量揭露，進階挑戰放在展開區。第一週 images 為空時顯示待補；有真實截圖時填：

```js
images: [
  { src: './images/lessons/w1-t02-step1.png', alt: '繁體中文 MakeCode 輸入工具箱中的按鈕 A 事件' }
]
```

陣列順序與步驟對應。檔案放 public/images/lessons，build 會複製到 dist/images/lessons；頁面可點圖片另開放大。截圖應由教師在官方 MakeCode 繁體中文介面擷取並核對。

## 地圖與作品展示

現階段使用 13 鄉鎮卡片，農產標示待核對。正式地圖請保留原穩定版，以 integration.gameUrl 連到核准的 HTTPS 遊戲；之後另行開發 GeoJSON 載入前須核對來源、行政界線與授權。

在 data/weeks.js 的 foods 中補入 product、feature、source、image 時，需要同步擴充資料卡顯示來源／圖片的 UI；目前只顯示文字欄位，尚未實作完整食農圖文呈現。請勿把未查核內容當成正式教材。

授權作品在 config 的 gallery 陣列加入 `{ title, weekId, url, approved: true }`。只放匿名且獲同意的作品；學生表單提交不會自動公開。

## 備份

備份原始碼、授權截圖與來源紀錄；私人表單回應留在校方核准的位置，不混入公開 Git。每次修改先跑測試與 build，再在獨立預覽檢查。原穩定版另行備份，不直接覆寫。
