## 4. 給 Codex：美工視覺協作指引

### 4.1 目前的設計方向：「南投走訪冒險地圖」

- **概念**：整個課程是一趟走訪南投的冒險。學生是食農大使，五週沿著一條足跡小路前進。
- **最搶眼的元素**：首頁全幅插畫（`heroScene()`）。其他地方保持安靜，不要搶走它的焦點。
- **色彩**（定義在 `styles.css` 視覺區塊的 `:root`）：

| 名稱 | 色碼 | 用途 |
|---|---|---|
| 天空 `--sky` | `#cfeaf2` | 首頁背景 |
| 茶園綠 `--tea` | `#2e7d4f` | 主要強調色 |
| 山林深綠 `--forest` | `#1d4a36` | 標題、深色區塊 |
| 日月潭藍 `--lake` | `#3b8db5` | 輔助色 |
| 陽光黃 `--sun` | `#f6c544` | 點綴、遊戲按鈕 |
| 紅隊 `--red-team` | `#d6493a` | 紅隊，綠隊用 `#2e8b57` |

- **字型**：標題用「霞鶩文楷 TC」（手寫筆記感，像大使日誌），內文用「思源黑體 Noto Sans TC」。由 `app.js` 動態載入 Google Fonts。
- **插畫**：全部是原創 SVG，寫在 `illustrations.js` 裡。**不要使用網路上的圖片或真實人物照片**，也不要畫出任何既有卡通角色或品牌吉祥物。
- **動態**：只有首頁腳印依序出現這一個動畫，並尊重「減少動態效果」設定（`prefers-reduced-motion`）。請不要在每張卡片加入場動畫。

### 4.2 CSS 協作規則（避免互相覆蓋）

`src/styles.css` 是單一檔案，前半段是 Codex 原本的樣式，最後面是附加區塊：

```
/* ===== 視覺改版：南投走訪冒險地圖 ===== */   ← Claude
（之後還有幾段 Claude 附加的小區塊）
```

**請 Codex 這樣做：**
1. 在檔案**最後面**新增自己的區塊：`/* ===== Codex 視覺：<主題> ===== */`。
2. 要改顏色，請改 `:root` 變數，不要寫死色碼。
3. 不要大量重排或刪除既有規則。要移除某條規則時，在移交單裡寫明原因。
4. 改完要檢查四種寬度：**390、768、1024、1366px**，都不能出現橫向捲軸。

## 5. 協作流程建議

### 5.1 讓老師電腦的資料夾成為 Git 工作資料夾（建議先做）

目前老師電腦的 `ai-food-course` 沒有 `.git`，Codex 改完的檔案無法直接推上 GitHub。建議由老師或 Codex 在「假日班-南投食農大使」資料夾執行：

```powershell
git clone https://github.com/lester47/ai-food-course.git ai-food-course-git
# 把舊資料夾裡的 teacher-src 複製過去（它不在 GitHub 上）
Copy-Item -Recurse .\ai-food-course\teacher-src .\ai-food-course-git\
```

確認沒問題後，再把 `ai-food-course-git` 改名成 `ai-food-course`。

### 5.2 Claude 與 Codex 輪流修改時

1. **開始前**：`git pull`，取得最新版本。
2. **建議用分支**：Codex 在 `codex/<主題>` 分支修改，推上 GitHub 後開 Pull Request，由老師按 Merge。合併進 `main` 才會上線，比較安全。
3. **完成後**：`npm test` 通過才推送。
4. **寫移交單**：Claude 寫在 `handoff/claude/`，Codex 寫在 `handoff/codex/`。檔名用 `YYYY-MM-DD_主題.md`。
5. 同一個檔案不要兩邊同時修改。真的要同時修改，先在移交單裡說好各自負責哪一段。
